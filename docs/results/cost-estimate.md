## Reading the numbers

- **deepvariant**: cheapest listed option is AWS EC2 us-east-1 (spot) at about $2.99 per genome; the cheapest on-demand option is AWS EC2 us-east-1 at $6.80, so spot saves about 56% if the workflow tolerates preemption.
- **gatk**: cheapest listed option is AWS EC2 us-east-1 (spot) at about $3.01 per genome; the cheapest on-demand option is AWS EC2 us-east-1 at $6.83, so spot saves about 56% if the workflow tolerates preemption.
- Compute is rarely the deciding factor at these prices. Where the customer's data already sits matters more: moving a 30x BAM (~60-100 GB) out of a cloud costs roughly $5-12 in internet egress alone (see `egress_gb` in `config/prices.yaml`), and data-residency rules can rule a region out entirely (the Canadian regions are listed for that reason).
- HealthOmics costs more per hour than EC2 but removes the cluster to run and maintain; its run storage is included above under an assumed 1,200 GiB static allocation.

## Method

1. Read each run's per-task measurements (docs/results/<label>/resources.tsv, written by every
   WDL task) and the region it covered (metrics.json).
2. Keep the tasks a production run would have: the caller, coverage QC and the VCF clean-up and
   QC steps. Region fetching, benchmarking and reporting exist only for validation.
3. Scale each task's wall time to a whole genome: read-driven tasks by genome size / region size
   and by target depth / observed depth; VCF-only tasks by genome size / region size.
4. Put each task on the cheapest listed machine that meets its requested CPU and memory, and
   price the hours on demand and on spot.
5. Report a range. Low and high come from the spread of per-megabase rates across profiles (the
   200 kb CI region and the 5 Mb full region), with 25% added to the high end for localisation,
   retries and the genome being harder on average than these regions.
