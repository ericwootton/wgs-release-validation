# Merging SV calls from two callers

Question: If a customer runs pbsv and Sniffles on PacBio HiFi data, how should the 2 call sets
be combined for the best SV calling results? Furthermore, would this result be better than the
results obtained using either caller alone?

All values listed here are based on [`sv-merge/metrics.md`](sv-merge/metrics.md) exported from
actual run results using `make sv-merge`. Calls generated by the long-read module (GIAB HG002,
PacBio HiFi Revio 48x, `chr20:1000001-6000000`) were evaluated against the GIAB v5.0q draft
benchmark. This evaluation used the same `truvari bench` and `truvari refine` settings as the
[hand-off](longread/QC_SUMMARY.md). Since this region contains 52 benchmark SVs, differences of 1
or 2 calls are within the range of noise.

## What was compared

| Strategy | How it was made | Calls of 50 bp or more |
|---|---|---:|
| pbsv | pbsv alone, PASS calls | 46 |
| sniffles | Sniffles alone, PASS calls | 46 |
| union | both call sets concatenated, nothing removed | 92 |
| collapse | the union after `truvari collapse` with its defaults (500 bp, 95% size and sequence similarity) | 51 |
| collapse_loose | the same, but merging at the benchmark's own thresholds (2,000 bp, 70%) | 48 |
| intersect | pbsv calls that `truvari bench` matched to a Sniffles call | 42 |

## Results after refinement

| Strategy | Found | Missed | False | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|
| pbsv | 48 | 4 | 2 | 0.953 | 0.923 | 0.938 |
| sniffles | 47 | 5 | 4 | 0.909 | 0.904 | 0.906 |
| union | 48 | 4 | 33 | 0.621 | 0.923 | 0.742 |
| collapse | 47 | 5 | 6 | 0.875 | 0.904 | 0.889 |
| collapse_loose | 47 | 5 | 5 | 0.889 | 0.904 | 0.896 |
| intersect | 48 | 4 | 1 | 0.975 | 0.923 | 0.948 |

Values and record counts before refinement are documented in
[`sv-merge/metrics.md`](sv-merge/metrics.md).

## What the results show

**A plain union is the worst option.** Since most events were detected by both tools, the union
contained two records for those events. Only one record can be matched during benchmarking, and
the second record was counted as a false call. After refinement, recall was no higher than
recall using pbsv alone. This was because all events detected by Sniffles were also detected by
pbsv.

**Collapsing the union fixes most of that, but it still loses to pbsv alone.** Using truvari's
default settings, collapse removed 41 variant call records which were duplicates of 40 other
records. Some pairs of records described the same event in 2 ways but were not similar enough to be
merged. Therefore, both records were retained. For an SVA insertion near 4.03 Mb, collapse retained
the Sniffles record which did not match the benchmark. This caused the true event to be counted as
both a missed variant and a false call. Merging records using the more permissive thresholds used
by the benchmark removed 1 additional false call, and nothing else changed.

**Most of the false calls left after collapsing come from Sniffles.** Sniffles made 4 calls
which were not included in the benchmark. These included 2 insertions near 1.60 Mb which pbsv did
not detect. They were supported by 3 and 6 reads, respectively, where Sniffles reports coverage
of only 3 to 7 reads. Another Sniffles call corresponded to the
aforementioned SVA insertion. The 4th variant was an insertion within a tandem repeat at 1.77 Mb
which pbsv also detected. When calls are merged using their union, all variants detected by either
tool alone are retained. Therefore, the first 2 variants are also retained.

**Requiring both callers to agree gave the best result.** Taking the intersection removed one of
the two false calls from pbsv, and nothing that pbsv found was missed after refinement. The
remaining false call was an insertion within a tandem repeat at 1.77 Mb, and both callers
detected it. Agreement between callers removes errors produced by only one caller. However, it
does not remove errors shared by them.

## Recommendation

For this data type and benchmark, provide customers with the pbsv call set. Add a higher-confidence
flag to variants also called by Sniffles, instead of merging the two call sets into one. This
allows customers who want to reduce false calls while retaining pbsv recall to restrict the set to
variants called by both callers. Do not use the merged union as the default deliverable. If a union
is required, collapse it and check it against the benchmark, because the default
settings did not merge all duplicates in this case.

## Limits

- There were 52 benchmark SVs in a single 5 Mb region from a single sample. The intersection
  outperformed pbsv by producing only 1 fewer false call. The rationale against a simple union
  comes from how duplicates are scored and therefore does not depend on sample size.
- v5.0q is a draft benchmark. Before refinement, all strategies missed the same two 33 kb
  deletions and 4 events within tandem repeats. Combining these 2 variant
  callers does not help there.
- For each event in the intersection, the pbsv representation was used. Using a
  different base caller or using `truvari collapse --keep maxqual` could change the
  version retained.
- Merging was performed using only truvari. SURVIVOR and Jasmine were not tested.

## Reproduce

```bash
make longread      # if not already run: calls, benchmark and hand-off
make sv-merge      # the six strategies above, about 6 minutes on 8 cores
```

The workflow is [`wdl/optional/sv_merge.wdl`](https://github.com/ericwootton/wgs-release-validation/blob/main/wdl/optional/sv_merge.wdl).
